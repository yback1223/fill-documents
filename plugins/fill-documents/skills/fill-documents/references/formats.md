# 서식 준비와 오류 복구

스킬의 기본 작성 범위는 표식 유무와 관계없이 문서 전체의 적용 작성란입니다. 아래 내용은 CLI의 편집 지원 범위입니다. 지원 밖의 빈 셀·별첨·부록도 조사 목록에 포함하고, 검증된 준비본이나 허용된 문서별 편집으로 보완합니다. 미확인 사실·미지원 편집은 `blocked`로 남기며 완료라고 보고하지 않습니다. [전체 작성 절차와 coverage 목록](full-document-completion.md)을 함께 적용합니다.

## 공통 입력

필드 이름은 영문자로 시작하고 영문자·숫자·밑줄만 사용하며 최대 64자입니다. `constructor`, `prototype`, `__proto__`는 사용할 수 없습니다. 모든 발견 필드는 필수입니다. 텍스트는 빈 문자열/공백만의 값을 받지 않고, 최대 10,000 Unicode code point 또는 서식이 정한 더 작은 상한을 적용합니다. 체크박스의 `false`는 유효한 입력입니다.

JSON 예:

```json
{"title":"정기 회의 결과", "body":"확인한 사실을 작성합니다."}
```

지원되는 명시 필드는 `inspect FILE` 또는 `templates show ID`로 확인하세요. 표식이 없는 작성란까지 자동 탐지하는 목록은 아닙니다. 예제의 키를 아무 서식에나 사용할 수는 없습니다. 원본은 50 MiB 이하, 압축 해제 합계는 128 MiB 이하입니다. 출력 폴더는 먼저 생성해야 합니다.

## HWP

HWP 5.x 본문 문단에 고유 `{{field_name}}`를 넣습니다. 한 이름은 한 번만 사용합니다. 기본 preserve는 문단 전체의 글자 서식이 균일해야 합니다. flow는 원래 항목 기호·라벨 등 고정 접두부의 혼합 서식을 유지하면서, 첫 표식부터 문단 끝까지 균일한 글자 서식을 가진 본문을 지원합니다. 표나 개체 내부 입력, 표식 이후의 혼합 서식, 암호화·배포용·서명·실행 스크립트·변경 이력 등 추가 기능은 지원하지 않습니다.

자체 서식의 일반 한글, 단일 줄바꿈, XML 특수문자는 확인했습니다. 연속 공백·연속 빈 줄·탭·문자 그대로의 `<br>`는 엔진이 다르게 처리할 수 있어 정확한 재읽기에 실패하면 `E_PRESERVATION`으로 저장하지 않습니다. 이런 입력이 필요하면 사용자와 협의해 지원되는 HWPX 서식을 사용하세요. 파일 확장자만 바꾸거나 원본을 자동 변환하지 않습니다.

HWPX로 변환한 결과를 HWP 편집 성공이라고 표시하지 않습니다. 엔진의 성공 응답 외에도 적용 수·생략·잔차 차이·문단과 글자 서식·실제 텍스트·비대상 스트림을 검사합니다. 이 검사는 실제 한컴 앱의 페이지 배치 검증과 별개입니다.

## HWPX

`{{field_name}}` 표식은 여러 text run으로 분리되어도 같은 문단 안에서 처리됩니다. 같은 이름을 여러 곳에 쓸 수 있습니다. 표식이 개체 경계를 가로지르면 거부합니다. 누름틀은 `CLICK_HERE` 형식이며 영문 필드 이름이 있고, 시작과 끝이 같은 문단 안에서 대응하고 텍스트 요소를 포함해야 합니다. 중첩 누름틀은 지원하지 않습니다.

원본 ZIP의 이미지·스타일·표 등 비대상 데이터를 유지하고, 텍스트가 바뀐 문단의 저장된 줄 배치 캐시는 제거해 문서 앱이 다시 배치하게 합니다. 기존 미리보기 이미지는 갱신하지 않으므로 탐색기 썸네일 대신 문서 본문을 열어 확인하세요.

## Word DOCX

문서에 `{{title}}`, `{{body}}` 같은 단순 표식을 입력하세요. 표식이 Word에서 여러 run으로 저장되어도 처리합니다. 같은 이름을 반복할 수 있으며 본문·머리말·꼬리말·각주·미주의 지원되는 텍스트를 채웁니다. 줄바꿈 문자열을 지원합니다.

조건식, 반복문, raw XML, 템플릿 코드, 매크로, 메타데이터 안의 표식은 사용하지 마세요. 사용 글꼴은 문서를 여는 기기에 따라 대체될 수 있습니다. 기본 서식은 Nanum Gothic 글꼴을 지정하지만 DOCX 자체에 폰트를 임베딩하지 않습니다.

## PDF

기존 AcroForm 텍스트 필드와 체크박스를 채웁니다. 선이나 빈칸만 그려진 PDF는 입력 폼이 아닙니다. 이런 파일은 PDF 편집기에서 먼저 폼 필드를 만들어야 합니다. PDF 페이지 본문의 일반 텍스트를 직접 고치거나 스캔 파일을 OCR하지 않습니다.

한글 글꼴을 전체 임베딩하고 appearance를 갱신합니다. 기본 `preserve`는 필드보다 긴 글과 한 줄 필드의 줄바꿈을 거부합니다. `flow`는 아래 방식으로 별지를 추가합니다. 이모지 등 포함 글꼴에 없는 문자는 거부합니다. 공백·숫자로 시작하는 원래 필드 이름은 `inspect`의 `sourceName`으로 확인하고 입력 JSON에는 함께 제공되는 안정적인 `field_...` 별칭을 사용합니다. PDF 안의 원래 이름은 바꾸지 않습니다.

XFA, 암호화, 서명된 문서, 문서 실행 동작, 읽기 전용·숨김·페이지에 연결되지 않은 필드, rich text/password/file selector/combed 입력 등 복잡한 폼은 지원하지 않습니다. 서명 값이 없는 빈 서명 칸은 변경하지 않고 입력 목록에서 제외합니다. 필드가 없는 PDF도 구조 검사는 가능하지만 채우기는 성공으로 처리하지 않습니다.

## 긴 내용과 페이지 이어쓰기

`fill ... --overflow flow`로 명시적으로 요청합니다. 기본 `preserve`는 기존 배치 속성을 유지하므로 긴 값이 저장되었다는 사실만으로 표시 성공을 주장하지 마세요. 두 모드 모두 텍스트를 잘라내지 않으며 서식/manifest의 글자 수 제한을 해제하지 않습니다. 기관이 정한 제출 쪽수 제한도 별도로 확인해야 합니다.

- DOCX: 입력의 LF를 실제 문단으로 나눕니다. 접두부는 첫 문단, 접미부는 마지막 문단에 두고 기존 정렬·글꼴·간격을 유지합니다. 자동 번호·목록·책갈피 등 복합 경계가 있는 다문단 입력은 거부합니다. 지원 본문과 일반 표에서 선택 문단의 묶음 및 선택 행의 분할 제한을 해제하고 exact 행 높이를 최소 높이로 바꿉니다. 기존 fixed 표 너비는 유지합니다. AutoFit 표는 grid·셀폭·본문폭이 명확한 경우에만 고정합니다. 대상의 글자 압축/줄바꿈 금지 및 불명확한 스타일 상속, 텍스트 상자·떠 있는 표·중첩 표·세로쓰기·대상 세로 병합은 거부합니다. 실제 페이지 수는 문서 앱 렌더로 확인합니다. 비대상 떠 있는 표 앞의 제목은 keepNext만으로 연결되지 않을 수 있습니다. 이 경우 해당 준비본에서 원래 절 시작에 명시 쪽 나눔을 두고 짧은/긴 결과를 다시 렌더 검수합니다. 엔진이 모든 고아 제목을 자동 수정한다고 주장하지 않습니다.
- HWPX: 확인된 수평 본문 표의 앵커와 줄 배치 캐시를 갱신합니다. 여러 실제 셀을 가진 한 업무행이 여러 페이지로 나뉘면 저장하지 않습니다. 여러 업무는 `--layout-profile`로 지정한 빈 행 영역에 레코드 배열을 전달하세요. 기존 행을 재사용하고 필요하면 중간 행을 복제하며 미사용 빈 행은 제거합니다. 표 폭·글꼴·경계선을 유지하고 연속 제목행을 반복합니다. 한 업무 자체가 여러 페이지로 나뉘면 `E_LAYOUT`입니다. 단일 열 본문 표와 일반 본문은 별도 흐름을 유지합니다. 임의 고정/중첩/세로 표를 자동 복구하지 않습니다.
- HWP: 고정 접두부 뒤 표식 영역이 균일한 고유 최상위 본문을 엔진으로 재배치하고 허용된 BodyText 변경만 원본에 이식합니다. 문서 정보·비대상 레코드·서식이 달라지거나 결과 텍스트가 페이지 밖이면 저장하지 않습니다. 엔진이 읽을 수 있는 모든 HWP가 이 보존 조건을 통과하지는 않습니다. 알려진 정확한 빈 스크립트 저장소만 예외로 보존하며 실제 스크립트는 거부합니다.
- PDF: `--layout-profile`로 원본 페이지·반복 문맥·안내 문구의 여백을 지정합니다. 원래 칸에 첫 부분을 두고 같은 크기·정적 양식의 추가 페이지에 나머지를 이어 씁니다. 추가 페이지마다 편집 가능한 본문 필드는 하나입니다. 원래 설명 페이지와 빈 서명 칸은 유지하고 새 페이지는 문서 끝에 추가합니다. 프로필 없는 넘침, 기본 appearance에서 칸 폭을 초과하는 무공백 토큰은 거부합니다. 청크를 결합해 원문 전체를 대조하며 기본 appearance 재생성도 검사합니다. 반복 문맥은 정적 표시이므로 원래 값을 수동 수정한 경우 재생성해야 합니다. v2 과거 결과 검증은 유지하지만 새 결과는 v3으로 생성합니다.

DOCX/HWP/HWPX의 CRLF와 CR은 기존 동작대로 LF로 정규화합니다. PDF 청크는 원문 substring을 그대로 저장합니다. `layout` 응답은 수행한 배치 처리를 설명하며 `visualValidation: not-performed`는 실제 뷰어 검수가 아직 없다는 뜻입니다. 자동 검사 뒤에도 사용 앱에서 전체 페이지의 잘림·겹침·글꼴을 확인하세요.

레이아웃 프로필과 구조화된 행 입력은 [프로필 안내](layout-profiles.md)를 따릅니다. 프로필은 특정 원본 파일의 SHA-256에 묶이며 필드·좌표를 임의 추정하지 않습니다. 반복 헤더와 새 페이지의 정적 잉크 충돌은 렌더로 확인해야 합니다.

## 저장·복구

- `E_FIELDS`: 오류에 표시된 필드 이름·타입·필수값·길이를 확인합니다. 알려지지 않은 키를 자동 폐기하지 않습니다.
- `E_COVERAGE`: 작성 대상 목록의 상태별 근거, 중복 항목, 누락·중복·미지 필드 연결을 확인합니다. 제외 선언으로 기존 필수값 검사를 우회할 수 없습니다.
- `E_LAYOUT`: 선택 영역을 안전하게 늘릴 수 없거나 한 업무행이 분할되거나 PDF 본문/안내가 들어가지 않습니다. 내용을 몰래 줄이지 말고 오류의 영역·이유를 확인한 뒤 다른 준비본을 사용합니다.
- `E_TEMPLATE_CHANGED`: 등록 정보·레이아웃 프로필·coverage 목록과 현재 준비본의 해시가 다릅니다. 현재 파일을 다시 조사하고 해당 정보를 갱신합니다. 등록 서식은 새 ID로 다시 등록합니다.
- `E_OUTPUT_EXISTS`: 원본 또는 결과가 이미 있습니다. 새 출력 이름을 지정합니다.
- `E_UNSUPPORTED` / `E_PRESERVATION`: 지원 범위 밖이거나 정확한 보존을 확인하지 못했습니다. 원본을 유지하고 다른 서식이나 사용 앱에서 처리합니다.
- `E_IO`: 폴더 존재·접근 권한·디스크·하드링크 지원을 확인합니다. 덮어쓰기로 우회하지 않습니다.
- 정리 경고: 남은 임시 파일·잠금의 생성 당시 경로가 표시됩니다. 이동된 경로는 현재 위치가 아닐 수 있습니다. 활성 작업이 없는지 확인하고 사용자 소유의 잔여물만 정리하세요. 잠금을 자동 탈취하지 않습니다.

로컬 사용자가 관리하는 안정된 출력/라이브러리 폴더를 사용하세요. 폴더 교체 검사가 있지만 다른 프로세스가 검사와 파일 작업 사이에서 경로를 바꾸는 모든 경합을 원자적으로 차단하지는 못합니다. 성공 후 출력 위치 변경 경고가 있다면 결과를 열기 전에 위치를 다시 확인하세요.
