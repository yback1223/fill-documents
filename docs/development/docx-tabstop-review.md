## 실제 확인 근거

- `lib/adapters/docx.mjs:50–62`는 문단의 모든 Word 자손 `tab`을 문자로 읽고, `docx-flow.mjs:208–220`도 같은 구분 없이 읽는다. 경로는 모두 `plugins/fill-documents/skills/fill-documents/` 기준이다.
- `docx-flow.mjs:257–267`은 분할 문단마다 원래 pPr를 보존한다. 따라서 정지점 하나와 `{{body}}`가 있는 문단에 `첫째\n둘째`를 넣으면 현재 추출 방식의 기대값은 `\t첫째\n둘째`, 분할 결과의 추출값은 `\t첫째\n\t둘째`가 된다. `docx.mjs:181–191`의 비교가 실패하는 경로와 설계의 설명이 일치한다. 이는 코드 대조 결과이며 이번 검토에서 실행 재현한 결과는 아니다.
- 직접 부모의 네임스페이스와 이름을 함께 검사하고 기존 순회·문단 경계를 유지하면 정지점은 제외하면서 실제 `w:r/w:tab`, `t`, `br`, `cr`은 계속 읽는다. 원본 속성이나 거부 규칙을 바꾸지 않아도 해결할 수 있다.
- `tests/xml-flow.test.mjs:327–365`에는 실제 run 탭·입력 탭·줄바꿈·서식 보존 검증이 있고, `368–395`에는 hyperlink 등 문단 확장 불가 경계 검증이 있다. 설계의 추가 검증은 실제 입력 성공, 문자 일치, 정지점 보존을 확인하므로 테스트 개수만 늘리는 계획이 아니다.

## 필수 검증 보완

**P2 / RV-01 — 기존 테스트 추출 도우미의 동일 오독을 새 검증에 복제하지 않는다.**

- 위치: `tests/xml-flow.test.mjs:29–32`의 `wordParagraphs`.
- 반례·영향: 이 도우미도 모든 자손 `tab`을 문자로 센다. 정지점이 복제된 두 번째 출력 문단을 `\t둘째`로 읽어 정상 수정본을 실패로 판정하거나 잘못된 기대값을 만들 수 있다.
- 조치: 새 정지점 회귀 사례는 명시적인 기대 문자 `첫째\n둘째`와 대조하고, 각 출력 문단의 pPr 정지점 위치·정렬 및 실제 run 탭을 따로 검사한다. 이 도우미를 재사용한다면 서식용 탭을 배제하도록 함께 수정한다. 실제 run 탭과 입력 탭 보존 사례도 유지한다.
- 차단 범위: 설계 및 두 파서 구현은 차단하지 않는다. 위 구분이 없는 검사를 수정 완료 근거로 사용할 수는 없다.

## 가정과 재검토 범위

인라인 래퍼 안의 run은 기존처럼 순회하며, 문단 확장 지원 범위는 늘리지 않는다는 설계 계약을 전제로 한다. 부모 검사에 Word 네임스페이스를 포함하고 최상위 노드의 부모 부재를 안전하게 처리해야 한다.

실제 EISMEA 원본·출력, 전체 작성 예시의 완결성, 런타임 테스트·빌드·ZIP 검증·렌더링은 이번 검토에서 확인하지 않았다. `nl`, `sed`, `rg`, `shasum -a 256`으로 지정 설계·관련 코드·테스트를 읽었으며 각 읽기 명령은 종료 코드 0이었다. 소스는 변경하지 않았다.

재검토는 두 모델의 추출 조건이 달라지거나, 서식 삭제·지원 범위 확대·보존 검사 완화가 추가될 때 해당 계약에 한정한다. 현재 설계대로 구현한 뒤에는 설계의 검증 1–5와 RV-01의 결과를 구현 완료 근거로 확보한다. 이 판정은 전체 예시 작성 완료나 운영 보안·성능 검증·배포 승인을 뜻하지 않는다.

## 2026-10-08 구현 정적 검토 추가

**진행 가능. 구현은 위 설계와 일치하며 추가 필수 수정은 없다. RV-01은 코드·검사 설계 대조 범위에서 해결됐다.** 실행 성공의 독립 검증을 뜻하지 않는다.

- 새 테스트 `64–71`은 hyperlink 안에서 여러 run에 나뉜 필드의 검색과 preserve 입력을 검사한다. flow의 인라인 래퍼 확장 거부 계약을 새로 허용하는 변경은 없다.

추가 정적 검토는 `nl`, `sed`, `rg`, `shasum -a 256`, 읽기 전용 `python3` 해시 대조로 수행했고 모든 명령이 종료 코드 0이었다. 총괄이 전달한 “수정 전 새 검사 3개 중 2개 실패, 수정 후 새 검사와 기존 xml-flow 103개 통과”는 전달받은 실행 결과로만 기록한다. 이번 리뷰어는 테스트를 실행하거나 해당 원시 실행 출력을 대조하지 않았다. 전체 테스트·빌드·ZIP 검증·실제 EISMEA 재생성 및 렌더링도 이 추가 검토의 확인 범위에 포함하지 않는다.

추가 비차단 가정과 재검토 조건은 최초 검토와 동일하다. 검토 대상 소스·검사는 수정하지 않고 이 리뷰 문서만 갱신했다.
