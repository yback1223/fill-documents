# 서식 유지 재검증 기록

2026-10-08. 이번 범위는 사용자가 지적한 외부 문서의 서식 파손과 부적절한 반복 시험 내용을 수정하는 것이다. 마켓 제출·공개 배포 완료를 뜻하지 않는다.

## 구현과 준비본의 구분

- HWP 엔진: 기존 항목 기호/라벨의 혼합 접두부를 유지하되 표식부터 끝까지 균일한 본문만 채운다. 원시 CHAR_SHAPE와 비대상 스트림을 보존하며 재열기 텍스트 범위를 검사한다. 중첩 표의 paragraph index는 본문 coverage에서 분리한다.
- DOCX 엔진: 입력 LF를 실제 문단으로 확장하고 원래 문단/run 속성을 유지한다. 다문단 목록·복합 범위는 거부한다. 공유 styles/settings와 비대상 ZIP 파트는 바꾸지 않는다.
- HWPX 엔진: 명시한 빈 업무행 영역의 레코드 배열, 행 재사용/복제/삭제, 원래 경계선과 연속 제목행 반복을 지원한다. 재열기 후 한 업무행의 여러 페이지 분할과 텍스트 범위를 검사한다. 일반 다열 표의 scalar 장문 분할도 거부한다.
- PDF 엔진: 원래 칸에 첫 청크를 남기고 같은 정적 양식의 새 페이지에 multiline 필드 하나씩 만든다. v3 매핑의 원문·위젯 연결·원래 서명·반복 문맥을 검사한다. v2 reader는 유지한다. 프로필 없는 넘침, 기본 AP에서 폭을 넘는 무공백 토큰, 안전하게 읽지 못하는 inline image 배경은 거부한다.
- 공통: 해시에 묶인 `layoutProfile`, `--layout-profile`, 엄격한 `rows` 입력 검사를 추가했다. HWPX rows는 파일 경로로만 사용하며 등록 ID 제약을 우회하지 않는다.

준비본에만 적용한 변경:

1. HWP는 실제 33개 항목에 표식을 붙였다. 일부 라벨 뒤 공백/입력 구간은 원본의 기존 본문 스타일을 지정했다. BMC 2쪽은 입력 범위 밖이며 그대로 남긴다.
2. HWPX는 첫 업무행 표식과 법인명 표식, 반복 영역을 명시했다. 원본 `단위: 천원`과 `사업예산(원)`의 모순은 준비본 열 제목을 `사업예산(천원)`으로 바꾸어 기록했다.
3. DOCX는 표지 4값을 preserve로 먼저 채우고 본문 3값을 flow로 채웠다. 표지 AutoFit 표는 본문폭보다 24twip 넓어 flow가 안전하게 거부하며, 이 기준을 넓히지 않았다.
4. DOCX의 비대상 떠 있는 표 앞 2.2 제목이 상세 결과 19쪽에 홀로 남았다. keepNext와 표 첫 문단 keepNext의 격리 후보 모두 실패했다. 준비본의 해당 제목(paraId `3B17EDF0`)에 `pageBreakBefore=1` 하나를 명시하여 제목/표가 같은 20쪽에 놓이게 했다. 엔진의 범용 고아 제목 자동 수정이 아니다. 이 준비본의 짧은 결과는 29쪽, 상세 결과는 30쪽이다.

- `npm run build`: 스킬/플러그인 ZIP 2종 생성, 종료 0.
- `npm run validate`: 격리 ZIP에서 기본 양식 32회와 장문 8회, 종료 0. 네트워크와 자식 프로세스는 차단한 검사 환경이다. 기본 HWPX 보고서는 일반 본문이므로 장문 양성을 유지했다. 실제 다열 행의 거부는 별도 회귀와 외부 시험으로 검증했다.
- 외부 4형식 × 짧은/상세 2종: 최종 번들 CLI의 inspect → dry-run(무파일) → fill → standalone validate, 원본/출력 해시 대조. 8회 성공.
- HWP/HWPX 저장 파일을 다시 열어 전체 페이지 SVG/PNG 렌더. DOCX는 실제 Arial이 있는 System Supplemental 폰트 환경에서 LibreOffice로 PDF를 만들고 전체 페이지 PNG 확인. PDF는 Poppler로 전체 페이지 확인.
- 독립 QA는 HWP 원시 레코드·스타일·입력 33개, HWPX 5열 레코드/행 순서/페이지별 헤더, DOCX 원문/문단/비대상 ZIP, PDF canonical fields/청크/빈 서명 field/widget/AP를 대조했다. 상세는 `layout-repair-qa.md`에 기록한다.

## 남은 한계

- 실제 Word·한컴·PDF 편집기 UI와 Claude·Codex 호스트 내 호출은 미검증이다. CLI/정적 렌더 검증을 해당 앱의 동작 확인으로 확대하지 않는다.
- DOCX 일부 EC Square 글꼴은 설치되지 않아 렌더러에서 대체된다. 실제 Arial 본문과 저장된 글꼴 속성 보존은 별도 확인했다.
- PDF 새 페이지의 구조 태그는 확장하지 않으며 정적 반복 문맥은 자동 동기화되지 않는다. 다른 뷰어의 재편집 줄바꿈은 별도 확인이 필요하다.
- HWP 표 내부, 임의 병합/중첩 반복 표, 불명확한 floating 영역, 스캔/일반 PDF 본문은 지원 완료가 아니다. 단일 HWPX 업무행으로 줄일 때 위/아래 경계선을 함께 유지할 수 없으면 거부한다.
- 외부 신청서의 모든 항목을 채운 제출 완성본이 아니다. 보고서에서 입력 범위와 그대로 남긴 부록/다른 서식을 구분했다.
