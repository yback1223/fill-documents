# DOCX 탭 정지점과 가시 문자의 구분

## 재현 근거와 범위

2026-10-08 EISMEA 전체 작성 예시의 긴 응답 3개에서 실제 CLI flow가 `E_PRESERVATION: DOCX 입력 결과를 원본 문단과 대조하지 못했습니다`로 중단했다. 원본 문단의 `w:pPr/w:tabs/w:tab`은 탭 정지점 서식이며, 본문 `w:r/w:tab` 문자가 없다. 그러나 `docx.mjs`의 paragraphText와 `docx-flow.mjs`의 paragraphModel이 모든 자손 `w:tab`을 문자로 읽었다. 새 문단에 정상적으로 복제된 pPr를 추가 탭 문자로 잘못 재읽어 원문 비교가 실패한다.

## 계약과 변경

가시 텍스트 모델은 해당 문단에 속하는 Word 네임스페이스 `w:r`의 **직접 자식** `w:t`, `w:br`, `w:cr`, `w:tab`에서만 문자를 읽는다. 인라인 래퍼 내부의 실제 run은 그대로 읽고, 중첩 문단은 기존대로 별도 취급한다. pPr/rPr/탭 정지점은 서식으로 보존하며 문자에 포함하지 않는다. 두 모델에 같은 제한을 적용한다. 허용 편집·필드 필수값·내용 재읽기·구조 보존 검사와 거부 규칙을 완화하지 않는다. 소스 XML을 자동 정리하거나 탭 정지점을 삭제하지 않는다. 새로운 공개 API나 의존성은 추가하지 않는다.

## 검증

1. pPr 탭 정지점 + 두 줄 입력인 최소 DOCX를 실제 fillDocument에 주어 수정 전 E_PRESERVATION 재현, 수정 후 성공을 확인한다.
2. 결과의 각 문단에 탭 정지점 위치·정렬이 그대로 복제되어 있고, 실제 run 탭 문자가 새로 생기지 않음을 검사한다.
3. 별도/동일 사례의 실제 w:r/w:tab 및 입력 문자열의 탭은 보존되어야 한다. 원본 문자열과 행 연결값을 재확인한다.
4. 기존 DOCX·XML flow 테스트 및 전체 npm test, 번들 빌드, 격리 ZIP 검증을 수행한다.
5. EISMEA 실제 예시도 원래 탭 정지점을 유지한 채 재생성·재열기·전쪽 렌더한다.

주요 위험은 래퍼 안에 있는 실제 본문 run 문자를 누락하는 것이다. 직접 부모가 run인 경우만 제한하므로 hyperlink/smartTag 같은 상위 래퍼와는 독립적이다. Word 텍스트가 실제로 run 직접 자식이 아닌 특수 구조는 현재 지원 범위를 넓히지 않는다.
