# 저장 경합 보완 설계

독립 통합 검증에서 두 가지 경합을 재현했다. lstat 뒤 rename 전 생성된 빈 공개 템플릿 폴더를 rename이 교체했고, realpath 뒤 temp open 전 심볼릭링크로 바뀐 출력 부모를 통해 다른 폴더에 기록했다.

## 템플릿 등록

기존 `.<id>.lock/staging`의 완성 후보 생성·해시 검증은 유지한다. 공개 목적지는 rename하지 않고 `mkdir(destination)`으로 독점 생성한다. 이 생성이 실패하면 기존 디렉터리를 변경하지 않는다. 후보 template 파일을 공개 폴더에 hardlink하고, 마지막으로 manifest.json을 hardlink한다. manifest hardlink 성공이 등록 커밋이다. 목록은 manifest가 없는 폴더를 진행 중으로 취급해 노출하지 않는다.

커밋 전 실패 시 자신이 생성한 공개 파일만 dev/ino 확인 후 해제하고, 자신이 생성한 공개 폴더가 같은 dev/ino이며 비었을 때만 rmdir한다. 예약·staging·그 안의 파일에도 동일한 소유권 규칙을 적용한다. 재귀 삭제하지 않는다. 독점 생성에 성공한 파일은 열린 handle의 stat로 소유권을 기록한 다음 내용을 쓴다. 다른 파일이 있거나 소유권이 달라졌으면 남기고 정리 경고에 생성 당시 경로와 이유를 포함한다. 중단된 공개 폴더나 잠금을 자동 탈취하거나 기존 항목을 교체하지 않는다.

## 출력 부모 경합

canonical 부모 경로의 lstat를 저장하고 디렉터리임을 확인한다. 임시 파일 생성 직후 및 결과 hardlink 직전에 같은 경로가 여전히 디렉터리이고 device/inode가 같은지 확인한다. 변경이 관찰되면 결과를 게시하지 않고 E_IO로 실패한다. 독점 생성한 임시파일은 handle stat로 소유권을 기록하며 정리 때 dev/ino가 일치해야 삭제한다. 커밋 전 실패라도 정리 실패 경고를 오류 details에 포함한다. 경고는 잔존 가능성·생성 당시 경로와 파일명을 제공하며, 이동된 파일의 현재 위치를 확인했다고 표현하지 않는다. 등록 실패에도 같은 계약을 적용한다.

hardlink 성공은 커밋이며 그 이후 검사나 정리 문제 때문에 실패로 바꾸지 않는다. 커밋 뒤 부모가 바뀐 것이 관찰되면 성공에 W_OUTPUT_LOCATION_CHANGED를 붙여 반환 경로를 재확인하도록 알린다. POSIX openat/Windows handle-relative APIs를 사용하지 않는 이 portable Node 구현은 검사와 파일시스템 호출 사이의 모든 경로 교체를 원자적으로 차단하지는 못한다. 권한 있는 로컬 사용자의 안정된 작업 폴더를 전제로 한다. 이 한계는 공개 형식·복구 문서에 명시한다.

## 검증

기존 동시 출력·동시 ID 등록·원본 불변·커밋 후 정리 실패 검사 유지. 추가로 대상 mkdir 직전 외부 빈 디렉터리 생성 시 기존 inode 유지+실패, 임시파일 open 직전 부모 symlink 교체 시 게시 없음+실패, 커밋 전 I/O 실패 시 미완성 템플릿 목록 미노출과 외부 파일 미삭제를 검증한다. 커밋 전·후 예약/staging에 생긴 외부 sentinel 보존, 임시파일 unlink 실패 정보 반환, 정리 완료 후 동일 ID 재시도 성공 및 잔여 경로 존재 시 무변경 실패도 확인한다. 완료 후 배포 runtime을 재생성하고 CLI 검사와 격리 ZIP 실행으로 실제 사용자 경로를 확인한다. 본 보완안 승인 시 기존 architecture.md의 rename 커밋 부분을 이 계약으로 갱신한다.
