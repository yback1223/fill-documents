# 0.1.0 검증 기록

검증일: 2026-10-08. 로컬 환경: macOS arm64, Node.js 25.9.0. 이 기록은 자동 검사, 독립 통합 검사와 실제 렌더 확인의 범위를 구분한다.

## 자동 검사

| 실행 | 실제 결과 |
| --- | --- |
| `npm test` | 63/63 통과: 공통 14, DOCX/PDF 25, HWP/HWPX 및 엔진 24 |
| `npm run build` | 플러그인 ZIP과 독립 스킬 ZIP 생성, 외부 라이선스와 실행 번들 포함 |
| `npm run validate` | 두 ZIP을 개발 폴더 밖 한글·공백 경로에 각각 풀어 총 32/32 서식 실행 통과. 네트워크와 외부 프로세스 실행을 차단한 상태 |
| `claude plugin validate plugins/fill-documents --json --strict` | 성공, 경고 없음 |
| `claude plugin validate . --json --strict` | 자체 marketplace 검사 성공, 경고 없음 |
| skill-creator의 `quick_validate.py` | 스킬 형식 검사 성공 |
| Agent Plugins 1.0 공식 JSON Schema + Python jsonschema | portable manifest 검사 성공 |

ZIP 검사는 각 서식의 조회, 채우기, 결과 검증, 원본 해시 보존 및 기존 출력 덮어쓰기 거부를 확인한다. `doctor`도 실제 런타임을 로드해 네 가지 형식의 서식을 읽는다. 스킬 검사에는 일회성 `uv run --with PyYAML --with jsonschema python` 환경을 사용했으며 제품에는 이 의존성을 넣지 않는다.

초기 소스는 Node.js 22.23.2에서도 62/62 검사를 통과했다. 이후 ZIP 사전 검사에 실제 압축 해제 크기 상한을 추가하고, 배포용 압축 엔진의 손상·과도한 해제 크기·복구 재시도 검사를 추가했다. 최종 소스 63/63과 형식별 ESM·압축 WASM을 포함한 최종 ZIP 32/32 검사는 위 Node.js 25.9.0에서 실행했다. 원격 OS별 결과는 아래 배포 기록과 구분한다.

생성 번들과 원문 그대로 유지한 외부 라이선스는 upstream 공백을 포함한다. 전체 `git diff --cached --check`는 이 부분에서 실패했다. 두 경로를 제외한 자체 작성 파일에 동일 검사를 실행한 결과는 통과했다. 라이선스 원문을 검사 통과 목적으로 바꾸지 않았다.

## 독립 통합 검사와 수정

구현 담당과 분리한 development-integrator가 CLI 정상·실패 흐름, 사용자 서식 등록, 읽기 재검증, 원본 보존과 저장 경합을 확인했다. 로컬 재현 자료와 보고서는 `.cache/integration-review/`에 보관하며 배포물에 포함하지 않는다.

- PDF 글꼴을 부분 포함했을 때 구조 검사는 성공하지만 실제 글리프가 깨지는 문제를 재현했다. 나눔고딕 전체 포함으로 수정한 뒤 네 서식을 렌더했다. 임베드된 글꼴 윤곽과 문자 매핑을 원글꼴과 대조하는 회귀 검사도 추가했다. 수정 전 동작으로 되돌리면 이 검사가 실패함을 확인했다.
- 등록·출력 도중 다른 파일이나 폴더가 생긴 경우 이를 지우지 않도록 생성 파일의 소유권을 확인한다. 템플릿은 manifest 하드링크 게시를 커밋 경계로 사용한다. 커밋 전 실패와 게시 후 정리 경고를 구분한다. 독립 재검사에서 외부 sentinel 보존, 이름 충돌, 부모 폴더 변경과 정리 실패 사례를 확인했다.
- 잘못된 UTF-8 JSON을 대체 문자로 받아들이지 않고 거부한다. 원본 변경, 필수값 누락, 미확인 키, 필드 없는 입력, PDF 영역 초과와 HWP 엔진이 보존하지 못하는 입력을 검사한다.
- ZIP의 선언 크기뿐 아니라 실제 압축 해제 크기를 제한한다. 33 MiB 데이터를 작은 크기로 위조한 헤더로 전달하는 회귀 사례가 거부됨을 확인했다.
- 첫 Windows CI에서는 글꼴 라이선스의 해시 검사 1개가 실패했다. 원문 LF를 CRLF로 변환하면 CI의 실제 해시와 정확히 일치함을 재현했다. 체크아웃 시 자동 줄바꿈 변환을 막는 `.gitattributes`의 `-text`로 원문 바이트와 소스 해시를 보존하도록 수정했다. 해시 검사나 원라이선스는 바꾸지 않았다. 수정본의 Windows 실행 상태는 배포 기록에 남긴다.
  로컬에서 `git -c core.autocrlf=true checkout-index --all --prefix=<임시 폴더>/`로 163개 추적 파일을 내보내 원문과 바이트 단위로 모두 같음을 확인했다.
- 수정 후 Windows 기능 테스트 63/63은 통과했다. 뒤이은 ZIP 검사에서는 검사기의 `--import`에 전달한 Windows 절대 경로를 Node가 `c:` 스킴으로 해석해 시작하지 못했다. `pathToFileURL`로 변환하도록 검사기를 수정했다. 제품의 입력 검증과 네트워크 차단 검사를 생략하지 않았다.

분할 ESM·압축 WASM 변경은 별도의 독립 검사도 실행했다. `python3 .cache/split-gzip-review/verify.py`와 추가 Node 재읽기 검사는 모두 종료 코드 0이었다. 두 ZIP에서 추출한 WASM은 잠긴 `@rhwp/core 0.8.7` 원본과 바이트 단위로 같고, 해제 크기는 11,821,756바이트, SHA-256은 `54cf95014312e605c51b98eb9021247ea79ef2bbd0a7080e11c011d0246e3989`였다. Node 권한으로 추출 경로에만 파일 접근을 허용하고 소스 접근 거부를 확인한 뒤 네트워크 없이 `doctor → HWP fill → validate → inspect` 및 값 6개·원본 보존 재검사를 통과했다. npm 소스 fallback과 손상·과도한 크기 엔진 거부도 확인했다.

## 실제 렌더 확인

| 대상 | 도구와 조건 | 관찰 결과 |
| --- | --- | --- |
| 채운 PDF 4종 | Poppler 26.04.0 | 한글과 필드 값 정상 표시, 관찰한 예시에서 잘림 없음 |
| 채운 DOCX 4종 | LibreOfficeDev 26.8.0.0.alpha0, 별도 임시 글꼴 설정으로 포함 나눔고딕 지정 | 각 1쪽으로 렌더, 관찰한 예시에서 한글·배치 정상, 원본 보존 |
| HWP/HWPX | 파싱·필드·텍스트·비대상 내용과 저장 후 재검사 | 자동 검사 통과. 한컴 원본 앱 렌더는 실행하지 않음 |

DOCX의 글꼴이 파일에 임베드된다는 뜻은 아니다. 수신 앱의 설치 글꼴과 배치 엔진에 따라 달라질 수 있다. Microsoft Word 및 한컴 앱에서의 실제 조작, 모든 길이의 입력, 모든 사용자 문서의 배치나 무손실 보존은 확인하지 않았다. Claude/Codex 호스트에서 모델이 전체 작업을 수행하는 종단 간 대화 검사도 실행하지 않았다.

## 공개와 심사 상태

공개 URL의 내용과 새로 복제한 저장소의 4개 형식 실행을 확인했다. 커밋 `9a7c25e`의 [원격 CI](https://github.com/yback1223/fill-documents/actions/runs/37729210480)는 Ubuntu Node 20·22, Windows Node 22, macOS Node 22에서 모두 성공했다. 각 환경의 63개 테스트와 ZIP 32회 검사, 빌드가 통과했다. 원본 한컴·Word 앱이나 호스트 모델의 대화 검증을 대신하지 않는다.

공식 디렉터리의 업로드·심사·승인은 별도 상태다. 온라인 확인 이력은 [배포 기록](../distribution.md)에 기록하며 자동 검사 성공을 공식 마켓 승인으로 해석하지 않는다.
